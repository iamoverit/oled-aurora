# OLED Aurora

Небольшая Windows-утилита: мягкая полупрозрачная анимация периодически проходит по верхней части выбранного монитора. Оверлей пропускает клики, не получает фокус и не мешает печатать в других приложениях.

Первый профиль рассчитан на эксперимент с **GIGABYTE AORUS FO48U**: верхние **20%**, максимальная непрозрачность **25%**, **6 секунд** каждые **180 секунд**. Реакцию монитора нужно проверить самостоятельно: приложение не получает показания фактической яркости панели и не гарантирует сброс её алгоритма затемнения.

## Скачать и запустить

Готовые сборки: [Releases](https://github.com/iamoverit/oled-aurora/releases).

Скачайте `OledAurora.exe` или архив `OledAurora-win-x64.zip`. Это автономная сборка Windows x64: отдельно устанавливать .NET не нужно. Сохраните приложение в постоянную папку, запустите, выберите монитор и нажмите **«Показать анимацию»**. Кнопка **«Сохранить и свернуть»** оставляет приложение в системном трее.

Сборка не подписана сертификатом издателя. Windows может показать сообщение о неизвестном издателе. Контрольные суммы файлов опубликованы вместе с релизом в `SHA256SUMS.txt`.

## Управление

| Действие | Способ |
|---|---|
| Показать анимацию сейчас | `Ctrl + Alt + F10` или меню трея |
| Пауза / продолжить расписание | `Ctrl + Alt + F11` или меню трея |
| Настройки | Двойной щелчок по значку в трее или повторный запуск `.exe` |
| Выйти | Правый щелчок по значку → «Выход» |

Горячие клавиши не перехватываются, если уже заняты другой программой; окно настроек показывает предупреждение. Предпросмотр использует текущие значения формы без сохранения. Изменения вступают в расписание после **«Сохранить и свернуть»**. Закрытие окна крестиком скрывает его; несохранённые изменения не применяются.

## Настройки

| Параметр | Диапазон / варианты | По умолчанию |
|---|---|---|
| Высота верхней области | 5–40% высоты монитора | 20% |
| Максимальная непрозрачность | 5–80% | 25% |
| Длительность | 2–20 с | 6 с |
| Интервал между началами циклов | 30–600 с | 180 с |
| Частота кадров | 30 / 60 | 30 |
| Анимация | Холодное сияние / дымчатая волна / северное сияние | Холодное сияние |
| Отрисовка северного сияния | Классическая / шейдерная (GPU) | Классическая |
| Монитор | Основной автоматически / конкретный экран | Основной |
| Пауза в полноэкранных приложениях | Вкл. / выкл. | Вкл. |
| Автозапуск при входе в Windows | Вкл. / выкл. | Выкл. |

Печать и мышь **не сбрасывают** таймер. Полноэкранность определяется по активному окну без рамки, перекрывающему выбранный монитор; обычное развёрнутое окно IDE не блокирует расписание. Ручной запуск разрешён при выключенном расписании и поверх полноэкранного приложения. Блокировка сеанса, отключение сеанса и сон останавливают анимацию; после возвращения начинается новый интервал без накопленных запусков. Если монитор отключён, используется основной.

В версии **0.2.0** добавлено северное сияние: зелёные, бирюзовые и приглушённые фиолетовые световые занавесы с плавно меняющимися складками. У всех трёх эффектов прозрачность постепенно уменьшается в пределах выбранной высоты; последние 6% области полностью прозрачны, поэтому нижний край окна не обрезает видимое свечение. Геометрия и затухание масштабируются вместе с диапазоном 5–40%. При обновлении выбранный эффект и остальные настройки версии 0.1.0 сохраняются.

В версии **0.3.0** для северного сияния можно сравнить два способа отрисовки. Выберите **«Северное сияние»**, затем **«Отрисовка северного сияния → Шейдерная (GPU)»** и нажмите **«Показать анимацию»**. Шейдер процедурно создаёт тонкие вертикальные лучи, складки световых лент и зелёно-бирюзовые переливы с фиолетовым верхним свечением. Классический вариант остаётся доступным и выбран по умолчанию, в том числе при загрузке старых настроек. **«Сохранить и свернуть»** сохраняет выбранный способ для следующих запусков по расписанию.

Шейдерный вариант использует HLSL Pixel Shader 3.0 через WPF `ShaderEffect`. Ему требуется аппаратная поддержка PS 3.0 в текущем Windows-сеансе. При недоступности аппаратного ускорения приложение использует классическое сияние, а в настройках показывает пояснение. Полноэкранность, прозрачность, частота кадров, плавное появление и исчезновение работают так же, как у классического варианта. Нагрузка на GPU зависит от разрешения, высоты области и частоты кадров; шейдерный вариант не обязательно быстрее классического.

Между циклами окно скрыто, обработчик отрисовки отключён. Служебный таймер срабатывает раз в секунду. Приложение не снимает скриншоты рабочего стола, не имитирует ввод и не отправляет данные по сети.

Настройки: `%LOCALAPPDATA%\OledAurora\settings.json`. Сохранение заменяет файл через временный файл. Если JSON повреждён, загружаются значения по умолчанию, а исходник сохраняется рядом как резервная копия. Журнал ошибок: `app.log` в той же папке. Автозапуск использует запись текущего пользователя `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\OledAurora` и не требует администратора. Если переместили `.exe`, выключите и снова включите автозапуск.

## Проверка с FO48U

В [инструкции GIGABYTE, стр. 22](https://download.gigabyte.com/FileList/Manual/AORUS_FO48U_UM_English_20220214.pdf) описан ASC: после пяти минут распознанного бездействия яркость уменьшается на 30%, после десяти — на 50%. Порог изменений изображения не опубликован.

1. Дождитесь заметного затемнения в обычном рабочем приложении.
2. Запустите один проход анимации и оцените, восстановилась ли яркость.
3. Если нет, увеличивайте непрозрачность и длительность постепенно. При необходимости увеличьте высоту области.
4. После успешного прохода проверьте расписание в течение 15–20 минут.

Размер прозрачного окна сам по себе не равен площади значимых для детектора изменений. Если комфортная анимация в верхних 20% не помогает, решение может не подходить для данной прошивки/режима монитора. SDR и HDR нужно проверять отдельно. Приложение не отключает ABL, не заменяет APCS/AOCS и не является средством предотвращения выгорания.

Защищённый рабочий стол Windows (UAC, экран блокировки) и эксклюзивный полноэкранный вывод не входят в поддерживаемые сценарии оверлея. Протестирована Windows 11 x64. На других конфигурациях Windows/DPI/GPU требуется проверка.

## Сборка

Нужны Windows и [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0).

```powershell
./scripts/Build.ps1
```

Сборка, проверки ядра и автономный `.exe` с архивом создаются в `artifacts/`. Параметр `-OutputDirectory artifacts/v0.2.0` позволяет собрать новую версию в отдельную папку, если прежняя сборка сейчас запущена. Проверить реальное окно на интерактивном Windows-рабочем столе:

```powershell
./scripts/Build.ps1 -SmokeTest
# Или для уже собранного файла:
./artifacts/OledAurora.exe --smoke-test C:\path\to\smoke-test.json
```

Smoke-проверка кратковременно показывает слабый оверлей, проверяет Win32-стили, сохранение фокуса, физические размеры, воспроизведение, скрытие и остановку отрисовки; дополнительно проверяет загрузку значка, регистрацию горячих клавиш через тот же механизм на тестовых F13/F14 и окно настроек. Рядом с отчётом создаётся `settings-preview.png`, отрисованный только из интерфейса приложения, без захвата рабочего стола. Проверка не изменяет пользовательские настройки или автозапуск.

Детерминированные проверки ядра запускаются отдельно:

```powershell
dotnet run --project tests/OledAurora.Checks -c Release
```

Каждая сборка также выполняет проверки фактических WPF-кадров на прозрачном фоне: все эффекты, несколько моментов анимации, минимальная/обычная/максимальная высота, 4K и масштабы Windows 100/150/200%. Проверяются прозрачный нижний запас, плавное затухание перед ним и изменение изображения во времени. Отчёт: `artifacts/visual-test.json`; рядом сохраняются кадры для визуальной проверки. Запустить отдельно:

```powershell
./artifacts/OledAurora.exe --visual-test C:\path\to\visual-test.json
```

PS 3.0 не выполняется в программном `RenderTargetBitmap`. Поэтому при наличии аппаратной поддержки дополнительные проверки выполняют **встроенный байткод шейдера на Direct3D9 HAL** в невидимой внеэкранной поверхности: проверяют видимость, изменение кадров и корректную premultiplied-прозрачность. Затем к результату применяется та же WPF-маска области для проверки нижнего затухания при разных размерах и DPI. Кадры: `shader-northern-lights-00.png` … `shader-northern-lights-11.png`. При недоступности GPU эта часть явно отмечается в отчёте как пропущенная; программный возврат к классическому сиянию проверяется всегда. Smoke-проверка дополнительно воспроизводит оба способа в настоящем прозрачном окне и проверяет переключатель настроек.

GitHub Actions собирает, проверяет WPF-кадры и упаковывает Windows x64 при push/PR. Проверка реального рабочего стола выполняется локально, поскольку обычный CI не гарантирует интерактивный сеанс.

## Устройство

- `OledAurora.Core` — настройки, атомарное сохранение, монотонное расписание, огибающая анимации.
- `OledAurora` — WPF, Win32 layered window, системный трей, горячие клавиши, мониторинг сеанса/дисплеев.
- `OledAurora.Checks` — проверки ядра без сторонних пакетов.

Оверлей использует `WS_EX_LAYERED`, `WS_EX_TRANSPARENT`, `WS_EX_NOACTIVATE`, `WS_EX_TOOLWINDOW` и `SetWindowPos` с `SWP_NOACTIVATE`. Манифест включает PerMonitorV2; позиция и размеры задаются в физических пикселях, включая отрицательные координаты дополнительных экранов. Плавные градиенты рисуются средствами WPF, без браузерного движка. WinForms используется только для значка в трее и списка экранов.

`Shaders/NorthernLights.hlsl` — исходник процедурного шейдера. При `dotnet build` и `dotnet publish` он автоматически компилируется в `ps_3_0` системной `d3dcompiler_47.dll` и встраивается в приложение; устанавливать DirectX SDK, `fxc` или дополнительные NuGet-пакеты не требуется. В шейдерном режиме CPU обновляет время и параметры окна, а расчёт цвета пикселей выполняет GPU. Шейдер не получает изображение рабочего стола. Внеэкранный Direct3D9-помощник используется только при `--visual-test`.
